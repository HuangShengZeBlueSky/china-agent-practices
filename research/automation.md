# 每日续研与断点接续规则

用户于 2026-10-25 授权长期按排期逐步完成研究。每日任务以 Asia/Shanghai 早上时段运行，从 2026-10-26 开始。任务是否实际启用、ID 和调度结果以 automation.json 为准。

调度负责唤醒一次研究工作；每次执行依靠仓库状态接着做。它不是一个永不结束的进程，也不保证固定模型或单次时长。GitHub 原有源码备份 Actions 仍为手动工作流，与这里的智能续研任务分开记录。

## 每次执行

1. 读取远端最新 README、AGENTS、research/README.md、method.md、schedule.md、progress.json、backlog.json 和最后日志。保留用户修改。
2. 恢复进行中的单元。没有进行中则选择当前阶段最早且依赖满足的任务；不要仅因日历进入下阶段就跳过缺口。
3. 用一手原文做实质研究，输出中文解释、证据、流程图与架构图。搜索摘要只进入候选池。
4. 同时推进技能台账的小批次。读取 catalog/skill-study/index.json 所指分片；入口共享阅读不代替每个 occurrence 的依赖与宿主核查。
5. 读已固定原文，只有发现变化才新增版本；保存许可、哈希、实际读取范围。无法备份则记原因。
6. 对照替代方案，查失败与反证，留下可控学习练习。未运行就明确未运行。
7. 将正文、来源、任务状态、技能分片和日志一起提交 GitHub，再读回确认。失败时保存可恢复材料并报告，不冒充已发布。
8. 中文汇报实质发现、可点开的成果链接、精确进度与下一步。周末增加覆盖缺口、结论复核和排期更新。

## 状态规则

任务完成需要 accepted evidence，而非日期到达。阶段到期但未达标，保留进行中并解释差距。新发现材料进入增量池，不挤掉冻结基线。用户更改优先级时同步排期并记录。

主线全验收、技能全量研究验收、未决事项处理完成后，输出综合学习手册并停用该续研任务。仍有阻塞时不能停止并声称全部完成；明确所需信息或资源，同时继续能做的任务。

## 执行范围

授权范围内可查询一手公开材料、备份可保存的原文、更新此私有仓库和研究台账。研究阶段不购买 API 额度、不启动训练、不执行未知上游程序、不进行真实业务写入、不改变仓库访问权限。需要具体实验资源时先给出可审查方案及已有静态成果。

工具不暴露模型选择或推理档位时不得声称已经设置“最高模型”。通过原文级阅读、独立实现对照、反证和验证保证质量。
