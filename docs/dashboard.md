# 研究看板的使用与维护

看板包含资料库、方法地图、学习路线、归档作者拆解和个人学习记录五个入口。数据来自本仓已审阅的来源目录与原创中文笔记，原文链接保留固定提交。默认发布版本仅向拥有者开放。

## 阅读方式

在资料库中输入项目、公司、技术机制或文件名，配合公司、工程主题、来源类型与阅读状态筛选。卡片适合逐项阅读，表格适合横向扫描。点击“查看拆解”可以看到具体文件、可迁移方法、核查日期、许可与证据边界；“阅读中文拆解”在页面内打开完整笔记。

方法地图将多个项目放在同一个工程问题下比较。学习路线围绕业务技能、工具调用、Agent 运行骨架和长期研究库四个目标组织，给出阅读顺序与应交付的产物。归档页提供第三方仓库的采集流程、统计口径、六个代表案例和可搜索的 2,792 条技能路径索引。

资料、正文阅读范围和上游是否实际运行分别记录。归档完整索引只表示确认路径存在，不能理解为已经逐项审阅。看板目前不会在线自动抓取新版本。

## 个人学习记录

星标收藏、未读／阅读中／已读／已实践状态、路线完成勾选和自由笔记保存在当前浏览器的本地存储。它们不会跨设备同步，也不会修改仓库中的证据状态。不同网址和本地预览属于不同浏览器来源，记录彼此独立。

在“我的学习”点击“导出学习记录”，可以下载包含笔记、状态、收藏与原文地址的 JSON 备份。清理浏览器数据前应先导出。当前没有内置导入或账号同步功能。

## 本地打开

在仓库根目录运行：

```bash
python3 scripts/build_dashboard.py
python3 -m http.server 8080 --directory dashboard
```

浏览器打开 `http://localhost:8080`。看板采用普通 HTML、CSS 和 JavaScript，没有构建服务器或业务后端依赖。生成过程使用 Python 标准库；Markdown 渲染器 Marked 17.0.5 已以 MIT 许可随附。

生成脚本使用 `catalog/` 中的审阅数据并读取本仓 Markdown，更新可读目录与网页数据。新增来源后先补中文拆解，再更新方法卡和路线中的引用。程序仅校验结构，不替代正文阅读和语义判断。

## 托管与下载包

`dashboard/` 可以作为静态目录托管。托管版会附上研究包下载入口；离线源码默认不配置该链接，以免出现指向不存在文件的下载按钮。需要部署下载入口时，可以为生成器指定 `--download-url` 并把对应 ZIP 放到托管目录。

本仓研究文本和看板源代码保存在同一份交付包中。发布至个人 GitHub 仓库和发布研究看板是两个独立动作，不能仅凭看板上线就宣称已经推送到个人 GitHub 仓库。
